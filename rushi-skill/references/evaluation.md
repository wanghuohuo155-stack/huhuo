## 目录

1. 三级评测
2. 触发评测细则

4. 生产遥测

## 1. 三级评测

| 级别 | 测什么 | 怎么测 | 何时跑 |
|---|---|---|---|
| L1 触发评测 | 会不会调用、会不会乱调用 | trigger.json + mock/provider 判官 | 每次发版（CI） |
| L2 效果评测 | 用了是否真的更好 | outcome.json + A/B + rubric 专家盲评 | 发布前抽样、季度复评 |
| L3 生产遥测 | 真实调用中的表现 | opt-in 遥测 + 反馈通道 | 持续 |

## 2. 触发评测细则

- 判官：默认 `mock-judge`（字符 bigram 重叠，确定性，用于 CI）；
  配置 provider 后可用真实 LLM 盲测（结果标注非 fallback）。
- 规则：should_not_trigger 容错为 0；总通过率 ≥80%；每 skill ≥5 条用例；
  至少 1 条诱饵必须是"应触发同书/同包另一个 skill"的跨 skill 混淆场景。
- 输出：`TEST_REPORT.md`，作为发布包硬性附件。

## 3. 效果评测细则

- 每个 outcome.json 任务必须可评分（文案、投资分析、决策清单、学习诊断等），
  不宣称通用提升。
- 协议：同一任务分别以"带包/不带包"执行，rubric 盲评打分，计算增量。
- 北极星：`效果增量 = 带包成功率 − 基线成功率`，目标 ≥ +20%。

## 4. 生产遥测

- opt-in、匿名、本地优先；事件：invocations / mis_trigger / positive / negative。
- `rushi evolve` 聚合遥测生成进化提案（误触发率超阈值 → 收紧 description；
  负面反馈 ≥3 → 复审边界；正面反馈 ≥10 → 提升 confidence）。
- 所有提案必须经人类审批 + 回归测试后才能发版。
