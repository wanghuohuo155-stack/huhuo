序章

入世使用说明书

把一本书，变成 一套能干的技能工具箱！

跟着本说明书一步一步走，

就像看小人书一样简单。

PowerShell
python rushi-skill\scripts\rushi-cli.py doctor
成功看到全部 ✅，说明电脑准备好啦
提示每张图都要照着做哦
02
准备 1

确认有 Python

Python 是让入世跑起来的引擎。

① 按键盘【Win】键，输入 powershell，回车

② 在黑框框里输入下面这行，回车

PowerShell
python --version
成功看到 python 3.11 或更高，OK！
报错提示找不到 python，去 python.org 下载并勾选 Add to PATH
03
准备 2

把入世装进 Codex

把整个 rushi-skill 文件夹，放进技能的家里：

（也可以直接对 Codex 说：帮我安装入世）

PowerShell
Copy-Item -LiteralPath 'D:\rushi-skill\rushi-skill' -Destination 'C:\Users\wangh\.codex-cli\skills' -Recurse -Force
成功skills\rushi-skill\SKILL.md 存在，OK！
报错权限被拒绝，让家长或 Codex 帮你执行
提示装好后，新开一个 Codex 对话才会生效
04
准备 3

给入世配一把钥匙

入世要请大模型帮忙，需要一把钥匙。

用 DeepSeek（推荐）就输入这 4 行：

PowerShell
$env:RUSHI_BASE_URL='https://api.deepseek.com'; $env:RUSHI_MODEL='deepseek-chat'; $env:RUSHI_API_KEY_ENV='DEEPSEEK_API_KEY'; $env:RUSHI_JSON_MODE='1'
成功没有报错 = 设置成功
报错提示找不到 DEEPSEEK_API_KEY，先去 platform 申请钥匙并设置
提示用 OpenAI 也可以：设 $env:OPENAI_API_KEY='你的钥匙'
05
第 1 步

走到项目家门口

先让黑框框进入入世项目目录：

PowerShell
cd D:\rushi-skill
成功提示符变成 D:\rushi-skill 开头
报错没有这个文件夹，先复制项目过来
06
第 2 步

给入世体检

每次开工前先体检，确认一切正常：

PowerShell
python rushi-skill\scripts\rushi-cli.py doctor --project D:\rushi-skill
成功看到全部 ✅（含 配置可读）
报错有 ❌，看红字提示是哪一项，修好再继续
07
第 3 步

建一个空项目

入世需要一个工作台，一条命令建好：

PowerShell
python rushi-skill\scripts\rushi-cli.py init --project D:\rushi-skill
成功看到 项目已初始化：D:\rushi-skill
报错提示路径错误，检查 --project 拼写
08
第 4 步

把书放进工作台

准备一个纯文本文件（书名.txt），放进 D:\ 下，

然后告诉入世：这本书叫什么、作者是谁：

PowerShell
python rushi-skill\scripts\rushi-cli.py ingest --project D:\rushi-skill --slug mybook --source D:\我的书.txt --title "我的书" --author "作者" --year "2026" --kind book
成功看到 S0 完成，books\mybook 出现
报错源文件为空/不存在，检查 --source 路径
提示slug 只能用小写字母和数字，比如 mybook
09
第 5 步

让入世先通读全书

入世会用 Adler 方法把整本书读懂，

然后写出一张《整书理解》地图：

PowerShell
python rushi-skill\scripts\rushi-cli.py stage --build D:\rushi-skill\books\mybook S1 --project D:\rushi-skill --mode provider
成功S1 -> done，books\mybook\BOOK_OVERVIEW.md 生成
报错S1 -> needs-provider：钥匙没配好；failed：输出不是合法 JSON（会自动重试一次）
提示这一步要花十几秒到几分钟，耐心等
10
第 6 步

派 5 个小分队去找方法

5 个提取器（框架/原则/案例/反例/术语）

同时从书里挑出最有用的方法：

PowerShell
python rushi-skill\scripts\rushi-cli.py stage --build D:\rushi-skill\books\mybook S2 --project D:\rushi-skill --mode provider
成功S2 -> done，candidates 里有 5 个 json
报错某一路 failed：正常会重试；连续失败就重跑一次 S2
提示书很长时，每一路最多挑 20 条，引文 ≤80 字
11
第 7 步

把候选变成正式清单

把 candidates 里最好的候选，写成 claims.jsonl。

这一步由 Codex 智能体自动做；格式长这样：

claims.jsonl · 每行一条 JSON
{"claim_id":"f01","skill_slug":"my-skill","kind":"framework","title":"标题","source_chapter":"章节","source_quote":"书里一字不差的句子","summary":"自己的话","tags":["tag"]}
成功books\mybook\claims.jsonl 存在且每行都是 JSON
报错引文不是原话，后面 S3 会打回来
提示source_quote 必须和书里一模一样，不能改写！
12
第 8 步

引文真假大检查

S3 会把每条引文拿去书里核对位置，

假话、拼接、改写的引文都会被揪出来：

PowerShell
python rushi-skill\scripts\rushi-cli.py stage --build D:\rushi-skill\books\mybook S3 --project D:\rushi-skill --mode provider
成功S3 -> done，fidelity=100%
报错有 unverified：把这条引文改回书里的原话，再重跑 S3
13
第 9 步

外部验证 + 构造技能

S4 检查方法在外面世界有没有佐证；

S5 把通过的方法组装成完整 SKILL.md：

PowerShell
python rushi-skill\scripts\rushi-cli.py stage --build D:\rushi-skill\books\mybook S4 --project D:\rushi-skill --mode provider; python rushi-skill\scripts\rushi-cli.py stage --build D:\rushi-skill\books\mybook S5 --project D:\rushi-skill --mode provider
成功S4 -> done 和 S5 -> done，skills\ 里有 SKILL.md
报错S5 failed：失败原因在 s5-review 文件夹里，修好重跑
提示偶发失败正常：原样重跑一次，多数会通过
14
第 10 步

给技能出考题

每个技能要有 tests\trigger.json 考题：

3 道该触发 + 2 道不该触发（诱饵）+ 1 道边界

智能体按 assets\templates\trigger.json.template 生成

PowerShell
python rushi-skill\scripts\rushi-cli.py check --build D:\rushi-skill\books\mybook --project D:\rushi-skill
成功S5 构造校验: 通过
报错提示缺 trigger.json 或缺某一段，补齐再继续
提示诱饵里必须有 1 道是'该触发另一个技能'的场景
15
第 11 步

连线 + 考试

S6 把技能之间的关系画成地图（INDEX.md）；

S7 用考题考试，诱饵错 1 道就 FAIL：

PowerShell
python rushi-skill\scripts\rushi-cli.py stage --build D:\rushi-skill\books\mybook S6 --project D:\rushi-skill --mode provider; python rushi-skill\scripts\rushi-cli.py stage --build D:\rushi-skill\books\mybook S7 --project D:\rushi-skill --mode provider
成功S6 -> done；S7 -> done（通过率与诱饵结果看 TEST_REPORT.md）
报错S7 failed：看 TEST_REPORT.md 哪道题答错，改 description 或考题
16
第 12 步

打包 + 过安检

把技能装进一个漂亮盒子（pack），

然后过 S9 安检——缺一份证据都不放行：

PowerShell
python rushi-skill\scripts\rushi-cli.py package --build D:\rushi-skill\books\mybook --project D:\rushi-skill --name my-pack --version 0.1.0; python rushi-skill\scripts\rushi-cli.py gate --pack D:\rushi-skill\packs\my-pack
成功S8 打包成功 + S9 发布闸门: 通过
报错闸门列出缺哪份证据（PROVENANCE/TEST_REPORT/GLOSSARY/INDEX），补好再打包
提示TEST_REPORT 必须 PASS 才能打包
17
第 13 步

安装进 Codex

先 dry-run 预习一下会装到哪里，

确认无误再去掉 --dry-run 真装：

PowerShell
python rushi-skill\scripts\rushi-cli.py install --pack D:\rushi-skill\packs\my-pack --host codex --scope user --dry-run
成功列出 → 目标路径\skill 名（dry-run）
报错拒绝安装到 pack 自身目录，换 --target 路径
提示host 可以是 codex / claude / cursor
18
第 14 步

让技能越用越聪明

把使用记录（telemetry.jsonl）喂给入世，

它会自动写出改进提案，等人类审批：

PowerShell
python rushi-skill\scripts\rushi-cli.py evolve --project D:\rushi-skill --pack D:\rushi-skill\packs\my-pack --telemetry D:\rushi-skill\telemetry.jsonl --out D:\rushi-skill\proposals
成功S10 进化: 生成 N 条提案（待人类审批）
报错未指定 --telemetry 且无遥测库：先准备 telemetry.jsonl
提示提案要人类审批后才改技能，不能自己乱改
19
急救卡

出错别慌

① 不认识命令 → 粘贴回原样，检查空格和引号

② 钥匙没配对 → 重新执行准备 3 的 4 行

③ S1/S2 显示 needs-provider → 钥匙没生效

④ 引文打回 → 打开书复制原句，别自己写

⑤ 还想不明白 → 把红字原样发给 Codex 问

PowerShell
python rushi-skill\scripts\rushi-cli.py doctor --project D:\rushi-skill
成功红字消失 = 修复完成
提示错误信息第一行最重要，先读它
